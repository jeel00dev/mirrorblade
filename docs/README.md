# MIRRORBLADE V2 — shared working directory

Everything about the V2 overhaul lives in `docs/`. Both agents (Codex and Claude Code) and the owner read and write here. Do not scatter findings elsewhere.

| File / folder | What it is | Who updates it |
| --- | --- | --- |
| `HANDOFF.md` | Running log of who is working, what was done last, what to pick up next. **Read this first.** | Every session, at start and end |
| `v2-audit.md` | Phase 0 audit of the V1 codebase (what works / broken / generic / redesign / refactor) | Codex, 11 Sep 2026 |
| `research-v2.md` | Reference palette sampling + Tetris / match-3 / bubble / UI research with sources | Codex, extended by Claude |
| `design-system.md` | OBSIDIAN MIRROR 2.0 tokens, spacing, radii, depth, type, icons, motion | Both |
| `feedback-matrix.md` | Per-event visual / audio / haptic / HUD / score / energy / camera / duration | Both |
| `IMPLEMENTATION_STATUS.md` | Feature ledger — update **every time** something is implemented, fixed or tested | Both |
| `CHANGELOG_V2.md` | Dated change log with files, reason, validation | Both |
| `BUGS.md` | Bug tracker (ID, severity, status, repro, expected, actual, fix, test) | Both |
| `balance-report.md` | Simulated / manual playtest results and tuning decisions | Claude |
| `game-over-animation-research.md` | Hit-stop, slicing feedback, sword timing and collapse references behind the katana game-over cinematic, with the event timeline | Claude, 12 Sep 2026 |
| `reference/original-reference.png` | **The primary visual reference.** The owner wants this material language across the whole game | Never modify |
| `reference/current-v1-*.png` | V1 desktop screenshots supplied by the owner showing the problems | Never modify |
| `qa/v1/` | Baseline V1 captures at 7 viewports + overlay diagnostic | Frozen |
| `qa/v2/` | V2 captures per screen per viewport (regenerated by `scripts/capture-screens.mjs`) | Regenerated |
| `../art/asset-manifest.json` | Every runtime asset: id, source, runtime file, purpose, construction | Both |

## Workflow rules (from the owner's brief)

1. Research → design → assets → implement → test. Do not skip to UI edits.
2. Fix block colour parity before anything else visual.
3. Update `IMPLEMENTATION_STATUS.md` and `CHANGELOG_V2.md` as you go, not at the end.
4. Record important bugs in `BUGS.md` before fixing them.
5. Responsive work is not done until screenshots at all target sizes have been looked at.
6. When unsure about visual direction, open `reference/original-reference.png`.

## Commands

```bash
npm run check                 # lint + unit tests + production build
npm run test:e2e              # Playwright suite (needs Chromium installed)
node scripts/capture-screens.mjs   # regenerate docs/qa/v2 screenshots
node scripts/simulate-runs.mjs     # balancing simulation → docs/balance-report.md
```
