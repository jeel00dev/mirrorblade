# Project workflow

These are the owner's standing project preferences.

- Start every new change in `docs/`: read `docs/README.md`, `docs/HANDOFF.md`, the relevant research/design notes, and `CONTRIBUTING.md`. Review recent Git commits to understand project progress.
- Before implementation, research the upcoming work on the internet and save a new, sourced Markdown research file in `docs/`. Use a new descriptive filename for each research effort; preserve earlier research.
- Keep the OBSIDIAN MIRROR UI theme consistent across the game. Follow `docs/design-system.md` and the existing tokens, materials, typography and controls.
- Keep the handoff, implementation ledger, changelog and relevant asset records current. Follow the contribution guide's validation requirements.
- Create new feature branches from a freshly fetched, fast-forwarded `main`, unless the owner explicitly names another base. Preserve local changes; do not reset or overwrite a collaborator's work. Continue on an already selected task branch when implementing that task.
